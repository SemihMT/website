Voice of the Ocean — Part 1

NPC AI in Unreal Engine 5

2024 · 8 min read
UE5 C++ AI School

Over the past few months, my team and I have been building an underwater world touched by the absence of humans and reclaimed by nature.

The game combines narrative and unique gameplay, allowing the player to interact with the world using their voice. One of the main interaction systems involves sea creatures, primarily pufferfish and sharks.

My role has been programming the AI for these underwater creatures. In this series, I'll share my thought process and how I implement their behaviors.

Some Context

Before diving into the implementation, it helps to cover the development environment and key terminology tied to Unreal Engine's AI systems. This is the first part of a multi-part series.

The Engine

We are using Unreal Engine 5.4. Its rendering capabilities and proven track record make it a natural choice for a project where visuals and narrative are central.

Unreal's AI Tools

Unreal provides several tools that simplify programming and iterating on NPC AI. Below are the systems I've been using and what I've learned about each.

AI Controller

An AI Controller is a subclass of Controller that allows AI systems to possess a pawn or character and take control of its movement.

Behavior Tree

Behavior Trees define the actions an AI takes. Developers create behavior by arranging composite nodes and tasks in the order they should execute, generally from top to bottom and left to right.

Composite Nodes

Composite nodes themselves do not execute logic; they structure the tree and control execution flow based on the success or failure of child nodes. The two main types are:

  • Selector — Executes child nodes until one succeeds. It chooses the most appropriate action from a prioritized list, picking the first one that succeeds.
  • Sequence — Executes all child nodes and only succeeds if all succeed. If any child fails, the entire sequence fails. This is used to define ordered steps that must all complete.
Task nodes can also return Aborted or InProgress, in addition to Succeeded and Failed. InProgress is useful when a task requires a condition to be met before continuing execution.

Blackboard

The Blackboard is a data container linked to a Behavior Tree. It allows reading and writing named keys at runtime, making the AI aware of events in the game world, such as player position or whether an enemy is within range.

Behavior Tree Tasks

Unreal's built-in task library is limited, so custom tasks are often required. Tasks can be created in Blueprints or C++. C++ tasks inherit from BTTask and override functions like ExecuteTask.

Design tasks with modularity and reusability in mind. Use Blackboard keys to share state between tasks instead of hardcoding values.

Environment Query System (EQS)

EQS allows AI agents to query their surroundings for a target location or actor. This is especially useful for positioning logic, such as finding a safe spot to flee or the nearest hiding spot.

The Environment Query Asset

Each query is defined by a Generator and one or more Tests. The Generator produces candidate items (locations or actors), and the Tests filter or score them to find the best result.

Generators

Generators can produce:

  • Actors of a specific class
  • The current location of the query context
  • A set of points around a context in various shapes: Circle, Cone, Donut, Grid, or Pathing Grid

Custom generators can be created by deriving from EnvQueryGenerator_BlueprintBase (Blueprints) or EnvQueryGenerator (C++).

Query Contexts

Contexts define the frame of reference for generators and tests. The built-in Querier context returns the actor running the query. Contexts can provide a single actor, multiple actors, a single location, or multiple locations.

  • EnvQueryContext_Item — The item generated by the generator.
  • EnvQueryContext_Querier — The pawn possessed by the AI Controller.

Custom contexts can be created by deriving from EnvQueryContext_BlueprintBase or EnvQueryContext.

Tests

Tests score or filter the items generated by a generator. Filtering removes items that do not meet criteria, while scoring determines the best option among the remaining candidates.

Scores can be clamped, weighted, and normalized, either absolutely (0 as the base) or relatively (lowest score as base). The scoring method can be Constant, Linear, Square, Inverse Linear, or Square Root.

Built-in tests include:

  • Distance — Measures direct distance between item and context.
  • Dot — Calculates the dot product of two vectors, useful for angle checks.
  • Gameplay Tags — Finds actors with specific tags.
  • Overlap — Checks if a shape at the item's location overlaps a collision channel.
  • Pathfinding / Pathfinding Batch — Checks if a navigation path exists and can score by path cost or length.
  • Project — Projects items inside geometry back onto the navmesh.
  • Trace — Performs line or shape traces, useful for line-of-sight checks.

Custom tests can be implemented in C++ by deriving from EnvQueryTest. Blueprint support for custom tests is not currently available.

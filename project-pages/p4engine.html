Solo Project

P4Engine — Bubble Bobble

2024 · Solo project · C++ / SDL2
GitHub ↗
C++ GPP School

Overview

P4Engine is a small game engine written in modern C++ and developed from scratch for the Programming 4 course at DAE. The architecture is inspired by the ideas presented in Game Programming Patterns, with a focus on modular systems and reusable design patterns that keep the engine flexible and easy to extend.

To validate the engine in a real project, I built a full recreation of the classic Bubble Bobble on top of it. The game serves as a practical test case for the engine's systems, including rendering, object composition, level loading, and gameplay logic.

Technical Highlights

  • Component system: GameObjects act as lightweight containers, while behaviour is implemented through attached components. A shared Component base class defines the interface, and concrete components such as TileComponent, PlayerComponent, and ZenChanComponent provide the actual functionality. This keeps objects modular and avoids deep inheritance hierarchies.
  • Service locator architecture: Global systems such as audio and rendering are accessed through a service locator. This allows implementations to be replaced or mocked without modifying the code that depends on them.
  • PPM-based level system: Levels are stored as .ppm image files where each pixel represents a tile in the game world. Pixel colours map to registered game object types, while comment lines in the file store per-pixel metadata such as enemy direction, player index, or movement speed. The engine reads these registrations at startup and constructs the level directly from the image.
  • Custom level editor integration: Standard image editors cannot manage metadata stored in PPM comment fields, so I developed a companion tool called PPMEdit. The editor allows levels to be painted visually while attaching metadata to individual pixels, producing files that can be loaded directly by the engine.

PPM Level Parser — colour registration

+

Each colour is registered with a factory lambda that constructs the appropriate game object. The parser calls these at load time for every matching pixel in the level image.

auto parser = GameSettings::GetInstance().GetParser();

// Tiles — colour maps to tile index and collider type
parser->RegisterColor({ 255, 128, 192 }, [](const glm::ivec2& pos, const std::optional& /*metadata*/)
{
    auto tileObject = std::make_unique(glm::vec3{ pos.x, pos.y, 0 });
    tileObject->AddComponent(0, ColliderType::Wall);
    return tileObject;
});

// Enemies — direction read from per-pixel metadata
parser->RegisterColor({ 0, 128, 255 }, [](const glm::ivec2& pos, const std::optional& metadata)
{
    auto zenChan = std::make_unique(glm::vec3{ pos.x, pos.y, 0 });
    auto direction = std::get(metadata.value().metadataMap.at("direction"));
    zenChan->AddComponent(direction, ColliderType::Trigger);
    return zenChan;
});

// Player — supports two players, number stored in metadata
parser->RegisterColor({ 0, 255, 0 }, [](const glm::ivec2& pos, const std::optional& metadata)
{
    auto player = std::make_unique(glm::vec3{ pos.x, pos.y, 0 });
    auto startingDirection = std::get(metadata.value().metadataMap.at("direction"));
    player->AddComponent(1, startingDirection);
    return player;
});

PPM Level Parser — metadata parsing

+

Metadata lines in the .ppm file follow the format # Metadata: (x, y) type values.... The parser reads the pixel coordinate, looks up the registered handler for that metadata type, and stores the result for use during object creation. 

// Metadata handlers registered at startup — each type knows how to parse its values
std::unordered_map m_metadataHandlers
{
    { "direction", [](const std::vector& values, Metadata& data)
    {
        if (values.size() >= 3)
            data.StoreMetadata("direction", glm::vec3{ std::stof(values[0]), std::stof(values[1]), std::stof(values[2]) });
    }},
    { "speed", [](const std::vector& values, Metadata& data)
    {
        if (!values.empty())
            data.StoreMetadata("speed", std::stof(values[0]));
    }},
    { "player", [](const std::vector& values, Metadata& data)
    {
        if (!values.empty())
            data.StoreMetadata("player", std::stoi(values[0]));
    }}
};

void LevelParser::ParseMetadata(const std::string& line)
{
    // Example line: "# Metadata: (2, 13) direction 1 0 0"
    size_t start = line.find('(');
    size_t comma = line.find(',', start);
    size_t end   = line.find(')', comma);

    int xCoord = std::stoi(line.substr(start + 1, comma - start - 1));
    int yCoord = std::stoi(line.substr(comma + 1, end - comma - 1));

    size_t metadataStart = end + 2;
    size_t nextSpace     = line.find(' ', metadataStart);
    std::string metadataType = line.substr(metadataStart, nextSpace - metadataStart);

    std::vector metadataValues;
    std::istringstream valueStream(line.substr(nextSpace + 1));
    std::string value;
    while (valueStream >> value)
        metadataValues.push_back(value);

    Metadata data{};
    const auto it = m_metadataHandlers.find(metadataType);
    if (it != m_metadataHandlers.end())
    {
        it->second(metadataValues, data);
        m_pixelToMetadataMap[{ xCoord, yCoord }] = data;
    }
}
